# ПР02: топики и типы сообщений

Типы получены командами ROS 2 Jazzy во время локального опыта.

| Полное имя топика | Тип | Назначение |
| --- | --- | --- |
| `/turtle1/cmd_vel` | `geometry_msgs/msg/Twist` | Издатель CLI задаёт скорость; нода `/turtlesim` подписана на команды |
| `/turtle1/pose` | `turtlesim/msg/Pose` | Нода `/turtlesim` публикует текущее положение и скорости; CLI `echo` их читает |

## Twist

Команда `ros2 interface show geometry_msgs/msg/Twist` показала два вектора
`linear` и `angular`, каждый с компонентами `float64 x`, `y`, `z`.

| Поле | Смысл |
| --- | --- |
| `linear.x` | Линейная скорость вдоль локальной оси x; у черепахи — вперёд при положительном значении |
| `linear.y`, `linear.z` | Линейные скорости по двум другим осям; в этом двумерном turtlesim не используются |
| `angular.x`, `angular.y` | Угловые скорости вокруг осей x и y; в этом turtlesim не используются |
| `angular.z` | Угловая скорость вокруг оси z; в turtlesim положительное значение поворачивает против часовой стрелки |

В обычном ROS соглашении линейная скорость выражается в м/с, угловая — в рад/с;
в turtlesim движение происходит в условной системе координат симулятора.
В опыте отправлено `{linear: {x: 1.0}, angular: {z: 0.5}}`; остальные компоненты
нулевые. Это команда скорости, а не координаты цели и не команда «проехать 1».

## Pose

`ros2 topic type /turtle1/pose` фактически вернула `turtlesim/msg/Pose`.
Для установленного Jazzy не используем вариант `turtlesim_msgs/msg/Pose`
из другого дистрибутива.

`ros2 topic echo /turtle1/pose --once` показала поля:

- `x`, `y` — координаты черепахи в системе симулятора;
- `theta` — угол ориентации в радианах;
- `linear_velocity` — текущая линейная скорость;
- `angular_velocity` — текущая угловая скорость.

## Почему /cmd_vel не сработал

`/cmd_vel` и `/turtle1/cmd_vel` — два разных полных имени.
У ошибочного `/cmd_vel` был тип `geometry_msgs/msg/Twist`, но 0 подписчиков.
У `/turtle1/cmd_vel` был тот же тип и подписчик `/turtlesim`.
Совпадение структуры данных не соединяет разные топики.
Подробные реальные выводы до/после находятся в [commands.md](commands.md).
