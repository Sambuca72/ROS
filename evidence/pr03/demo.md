# ПР03: первая нода — поза и команда

Задание: https://ros.lms.ci.nsu.ru/practices/pr03.
Дата проверки: 2026-10-05. Среда: Ubuntu 24.04, ROS 2 Jazzy,
`ROS_DOMAIN_ID=16`, course kit `v1-w03`. Тип позы установлен командой
`ros2 topic type /turtle1/pose --no-daemon --spin-time 3`:
`turtlesim/msg/Pose`.

## Реализация

Сохранён пакет `turtle_bringup` из ПР02. Рядом создан пакет `patrol`:

```bash
cd src
ros2 pkg create --build-type ament_python --node-name patrol \
  --license Apache-2.0 patrol --dependencies rclpy geometry_msgs turtlesim
cd ..
```

`package.xml` содержит зависимости `rclpy`, `geometry_msgs`, `turtlesim`.
`setup.py` устанавливает исполняемую команду `patrol`.

В `src/patrol/patrol/patrol.py` нода `/patrol` хранит последнюю позу в
`last_pose`. Подписка `pose_subscription` также хранится как поле объекта;
её callback только обновляет `last_pose`. Издатель отправляет `Twist`
в относительное имя `cmd_vel`. Таймер с периодом 0,1 секунды вызывает
чистую функцию из `src/patrol/patrol/command.py` и публикует результат:

- До первой позы все компоненты команды равны нулю.
- При наличии позы `linear.x=0.5`, `angular.z=0.3`, остальные компоненты нулевые.

Нода не вычисляет маршрут из координат: по заданию достаточно отличать
отсутствующую позу от полученного сообщения. Динамические параметры
и необязательное рисование мышью не добавлены.

## Сборка и чистые тесты

```bash
source /opt/ros/jazzy/setup.bash
colcon build --symlink-install --packages-select patrol
source install/setup.bash
python3 -m pytest src/patrol/test -v
ros2 pkg executables patrol
```

Сборка успешна; её вывод включён в `tests.txt`. Команда обнаружена:
`patrol patrol`. В `tests.txt` записан фактический результат: 6 passed.
Три теста функции проверяют отсутствие позы, обычное сообщение и
независимость возвращаемых изменяемых сообщений. `rclpy.init` для этих
тестов не требуется. Ещё три проверки — copyright, flake8 и pep257.

## Как повторить опыт вручную

В каждом терминале из корня workspace:

```bash
source /opt/ros/jazzy/setup.bash
source install/setup.bash
export ROS_DOMAIN_ID=16
```

Не запускайте teleop или дополнительного издателя команд.
Для первого наблюдения turtlesim должен быть остановлен.
В терминале B запустите:

```bash
ros2 run patrol patrol
```

В терминале C:

```bash
ros2 topic echo /cmd_vel --once
```

Команда до первой позы нулевая. В выполненном автоматизированном опыте
подписчик-наблюдатель получил 4 нулевые команды до запуска turtlesim.

Затем в терминале A:

```bash
ros2 launch turtle_bringup sim.launch.py
```

В локальном автоматизированном опыте использован тот же исполняемый
симулятор напрямую: `ros2 run turtlesim turtlesim_node` с
`QT_QPA_PLATFORM=offscreen`. Настоящие процессы ROS работали без видимого
окна; для ручной демонстрации используйте обычный графический сеанс.

## Дефект: имя разрывает связь

Оставьте patrol без remap в B. В C:

```bash
ros2 node list --no-daemon --spin-time 2
ros2 node info /patrol --no-daemon --spin-time 3
ros2 topic info /cmd_vel --verbose --no-daemon --spin-time 3
ros2 topic info /turtle1/cmd_vel --verbose --no-daemon --spin-time 3
ros2 topic echo /turtle1/pose --once
```

Реальный граф показал `/patrol` и `/turtlesim`; `/pr03_monitor` — отдельный
наблюдатель опыта, не часть решения. У patrol есть подписка на позу и
издатель `/cmd_vel`. Относительное имя при корневом namespace разрешается
в `/cmd_vel`, тогда как turtlesim подписан на `/turtle1/cmd_vel`.

| Этап | Топик | Издателей | Подписчиков | Результат |
| --- | --- | --- | --- | --- |
| Дефект | `/cmd_vel` | 1 | 0 | Ненулевая команда не доставляется turtlesim |
| Дефект | `/turtle1/cmd_vel` | 0 | 1 | Симулятор не получает команды patrol |
| Исправление | `/turtle1/cmd_vel` | 1 | 1 | Команды доставляются, черепашка движется |

Измерительный подписчик `/cmd_vel` был удалён перед снятием графа,
чтобы он не увеличивал число подписчиков в таблице. Поза в двух снимках
с интервалом 1,5 секунды совпала:

```json
{
  "x": 5.544444561004639,
  "y": 5.544444561004639,
  "theta": 0.0,
  "linear_velocity": 0.0,
  "angular_velocity": 0.0
}
```

После запуска симулятора patrol уже публиковал `linear.x=0.5`,
`angular.z=0.3`, но движения не было. Тип сообщения правильный;
причина дефекта — разные полные имена топиков.

## Исправление через remap

Остановите только patrol в B через Ctrl+C и запустите:

```bash
ros2 run patrol patrol --ros-args -r cmd_vel:=/turtle1/cmd_vel
```

В C повторите `node info`, `topic info` и `topic echo` из предыдущего
раздела для `/turtle1/cmd_vel`. Период таймера, тип сообщения, скорости,
домен и подписка позы остаются теми же; изменено только разрешение имени
выходного топика. В графе теперь 1 издатель и 1 подписчик turtlesim.
Фактическая поза после исправления:

```json
{
  "x": 6.715409755706787,
  "y": 8.393157005310059,
  "theta": 2.356800079345703,
  "linear_velocity": 0.5,
  "angular_velocity": 0.30000001192092896
}
```

Изменение координат и ненулевые измеренные скорости доказывают получение
команды. Последняя поза поступает в ноду: до симулятора команда была
нулевой, после появления позы стала ненулевой.

## init, spin, callback и Ctrl+C

- `rclpy.init(args=args)` создаёт контекст ROS, подключает транспорт
  и обрабатывает ROS-аргументы, включая remap.
- Конструктор `Patrol` создаёт ноду и её подписку, издателя и таймер.
- `rclpy.spin(node)` обслуживает события executor: вызывает callback
  подписки при сообщении и callback таймера при наступлении периода.
  Он работает до завершения контекста или прерывания.
- `on_pose` сохраняет последнее сообщение. `on_timer` выбирает команду
  через чистую функцию и передаёт её издателю. Эти функции выполняются
  при обработке событий, а не в отдельном ручном бесконечном цикле.
- Ctrl+C посылает SIGINT. В Python обрабатываются `KeyboardInterrupt`
  и `ExternalShutdownException`; в `finally` уничтожается нода,
  затем активный контекст завершается через `rclpy.shutdown()`.

Остановка процесса прекращает новые публикации, но не отправляет
мгновенную нулевую команду. Turtlesim некоторое время продолжает
выполнять последнюю команду, затем останавливается по своему тайм-ауту.
В опыте после SIGINT у patrol ожидание нулевых скоростей заняло
0.974 секунды. Фактическая поза после остановки:

```json
{
  "x": 4.753149509429932,
  "y": 5.742112159729004,
  "theta": -0.494385302066803,
  "linear_velocity": 0.0,
  "angular_velocity": 0.0
}
```

Затем ещё 1 секунду проверялись неизменность позы и отсутствие новых
команд. Только после этого остановлен turtlesim. Численные результаты
опыта приведены в этом документе.
